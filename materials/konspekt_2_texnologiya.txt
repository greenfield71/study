5-BO'LIM. NODE.JS ASOSLARI
============================================================

5.1. NODE.JS NIMA?
------------------
Chrome'ning V8 dvigateli asosida qurilgan, JavaScript'ni brauzerdan tashqarida (serverda) bajaradigan ochiq kodli, kross-platforma muhit.
- V8 — JS tez bajariladi; hodisaga asoslangan bloklamaydigan I/O; npm — katta ekotizim; Windows/macOS/Linux.
- Versiyalar (2026-okt): 24 — Active LTS (production uchun), 26 — oktyabrda LTS ga o'tadi. Production'da faqat LTS.
- Tekshirish: node --version

5.2. ARXITEKTURA (YUQORIDAN PASTGA)
-----------------------------------
Sizning kodingiz (app.js, Express) → Node.js standart kutubxonasi (fs, http, path, events, stream) → C++ bindings → V8 (JS dvigateli) + libuv (event loop, thread pool) → Operatsion tizim (fayl tizimi, tarmoq, protsesslar).
- V8 — JS kodini mashina kodiga kompilyatsiya qiladi (JIT).
- libuv — event loop va asinxron I/O; thread pool (odatda 4 ta oqim).
- Bitta asosiy oqim: JS kodi bitta oqimda bajariladi; og'ir I/O OS yoki thread pool'ga topshiriladi.

5.3. EVENT LOOP BOSQICHLARI (TARTIB BILAN)
------------------------------------------
1. timers — setTimeout, setInterval callback'lari
2. pending callbacks — ba'zi tizim (tarmoq) xatolari callback'lari
3. poll — I/O callback'lari (fayl, tarmoq); yangi hodisalarni kutadi
4. check — setImmediate callback'lari
5. close callbacks — yopilish hodisalari (socket.on('close'))

Ish bor ekan tsikl takrorlanadi. Microtask'lar: har callbackdan keyin avval process.nextTick navbati, so'ng Promise (microtask) navbati to'liq bajariladi.

Bajarilish tartibi (amalda):
    console.log('sync 1');
    setTimeout(() => console.log('timeout'), 0);
    Promise.resolve().then(() => console.log('promise'));
    process.nextTick(() => console.log('nextTick'));
    console.log('sync 2');

Natija: sync 1 → sync 2 → nextTick → promise → timeout.
Eslab qolish: sinxron → nextTick → Promise → timers.

5.4. ASINXRON KOD: 3 BOSQICH
----------------------------

a) Callback:
    const fs = require('fs');
    fs.readFile('data.txt', 'utf8', (err, data) => {
      if (err) { console.error('Xato:', err.message); return; }
      console.log('Fayl:', data);
    });
    console.log('Bu birinchi chiqadi!');   // avval shu, keyin fayl

- Error-first konvensiya: callback'ning 1-argumenti — xato (err), qolganlari — natija.
- Callback hell: ichma-ich callback'lar piramidasi (getUser → getOrders → getItems) — o'qish qiyin, xatolarni har darajada alohida tekshirish kerak. Yechim: Promise va async/await.

b) Promise:
Holatlar: pending (kutilmoqda) → fulfilled (resolve(value)) yoki rejected (reject(error)).
- .then() — muvaffaqiyat natijasi · .catch() — xatoni ushlaydi · .finally() — har doim bajariladi · Promise.all() — parallel bajarish.
    const fs = require('fs/promises');
    fs.readFile('data.txt', 'utf8')
      .then((data) => data.toUpperCase())
      .then((text) => console.log(text))
      .catch((err) => console.error(err.message))
      .finally(() => console.log('Tugadi'));

Promise zanjiri callback hell o'rniga tekis (flat) kod beradi.

c) async/await:
    const fs = require('fs/promises');
    async function main() {
      try {
        const data = await fs.readFile('data.txt', 'utf8');
        console.log(data.toUpperCase());
      } catch (err) {
        console.error('Xato:', err.message);
      } finally {
        console.log('Tugadi');
      }
    }
    main();

- async funksiya doim Promise qaytaradi; await Promise tugashini kutadi, oqimni bloklamaydi; xato try/catch/finally bilan.
- await ishlarni ketma-ket bajaradi; bog'liq bo'lmagan ishlar uchun parallel:
    const [a, b] = await Promise.all([
      fs.readFile('a.txt', 'utf8'),
      fs.readFile('b.txt', 'utf8'),
    ]);

8.1. ER MODEL ASOSIY TUSHUNCHALARI
----------------------------------
- Entity (mohiyat) — real obyekt (User, Project, Task) → jadval/kolleksiya.
- Attribute — xususiyat (name, email, status, deadline).
- Primary key (PK) — yozuvning yagona identifikatori: id (SQL), _id (MongoDB).
- Relationship — mohiyatlar orasidagi bog'lanish.
- Foreign key (FK) — boshqa mohiyat kalitiga havola: Task.projectId → Project.id.
- Cardinality — bog'lanish soni: 1:1, 1:N, M:N.

Task Manager ER: User(id, name, email unique) 1—N Project(id, name, deadline, FK userId) 1—N Task(id, title, points, status, FK projectId, FK assigneeId); User 1—N Task ("mas'ul"); Task M—N Tag(id, name) ("teglanadi").
M:N: SQL'da bog'lovchi jadval orqali; MongoDB'da ID'lar massivi.

8.2. MUNOSABATLAR: SQL VA MONGODB
---------------------------------

- 1:1 -> Misol: User—Profile; PostgreSQL + Prisma: Profile.userId + @unique; MongoDB + Mongoose: embed yoki ref
- 1:N -> Misol: Project—Task; PostgreSQL + Prisma: Task.projectId FK; Project.tasks Task[]; MongoDB + Mongoose: Task.project: ObjectId (ref:'Project')
- M:N -> Misol: Task—Tag; PostgreSQL + Prisma: yashirin bog'lovchi jadval: tags Tag[] / tasks Task[]; MongoDB + Mongoose: havolalar massivi tags:[ObjectId]

- Embed — birga o'qiladigan, kichik, mustaqil o'smaydigan ma'lumot uchun.
- Reference — mustaqil o'sadigan yoki ko'p joyda ishlatiladigan ma'lumot uchun.

8.3. SQL YOKI NOSQL?
--------------------
- Qat'iy sxema va cheklovlar -> MongoDB + Mongoose (hujjatli, NoSQL): Moslashuvchan hujjatlar (JSON/BSON)
- JOIN va murakkab so'rovlar tabiiy -> MongoDB + Mongoose (hujjatli, NoSQL): Tuzilma tez o'zgaradigan loyihaga qulay
- Prisma: type-safe klient, o'rnatilgan migratsiya -> MongoDB + Mongoose (hujjatli, NoSQL): Mongoose: sxema, validatsiya, middleware
- Mos: o'zaro bog'langan, aniq tuzilmali ma'lumot -> MongoDB + Mongoose (hujjatli, NoSQL): Mos: katalog, kontent, ierarxik ma'lumot

Qoida: ma'lumotlar kuchli bog'langan bo'lsa — SQL; tuzilma tez o'zgarsa — MongoDB.

8.4. MONGOOSE: SXEMA VA MODEL
-----------------------------
    const { Schema, model } = require('mongoose');
    const taskSchema = new Schema({
      title:   { type: String, required: true },
      points:  { type: Number, min: 1 },
      status:  { type: String, enum: ['todo','doing','done'], default: 'todo' },
      project: { type: Schema.Types.ObjectId, ref: 'Project', index: true },
      tags:    [{ type: Schema.Types.ObjectId, ref: 'Tag' }],
    }, { timestamps: true });
    module.exports = model('Task', taskSchema);

- Schema — tuzilma, turlar, validatsiya (required, enum, min). Model — kolleksiya bilan ishlash interfeysi (Task.find(), Task.create()). ref — boshqa kolleksiyaga havola, populate bilan yuklanadi. timestamps — createdAt, updatedAt avtomatik.

Mongoose CRUD:
    await Task.create({ title:'ER model', points:5, project: projectId });          // CREATE
    const todo = await Task.find({ status:'todo' }).populate('project','name')
                           .sort({ createdAt:-1 });                                 // READ
    await Task.findByIdAndUpdate(id, { status:'done' }, { new:true });              // UPDATE
    await Task.findByIdAndDelete(id);                                               // DELETE

- { new:true } — yangilangan hujjatni qaytaradi; populate — JOIN'ga o'xshash; o'chirishda bog'liq hujjatlarni o'zingiz tozalaysiz.

8.5. PRISMA: SXEMA VA CRUD
--------------------------
    model Task {
      id        Int      @id @default(autoincrement())
      title     String
      points    Int?
      status    String   @default("todo")
      projectId Int
      project   Project  @relation(fields: [projectId], references: [id])
      tags      Tag[]
    }
    model Tag {
      id    Int    @id @default(autoincrement())
      name  String @unique
      tasks Task[]
    }

- @id, @default — PK va standart qiymat; @relation — FK maydoni va havola; Tag[] — yashirin M:N (bog'lovchi jadvalni Prisma o'zi yaratadi); Int? — NULL bo'lishi mumkin.
    await prisma.task.create({ data:{ title:'ER model', points:5,
            project:{ connect:{ id:1 } } } });                        // CREATE
    const todo = await prisma.task.findMany({ where:{status:'todo'},
            include:{ project:true } });                              // READ
    await prisma.task.update({ where:{id}, data:{status:'done'} });   // UPDATE
    await prisma.task.delete({ where:{id} });                         // DELETE

- connect — mavjud yozuvga bog'laydi; include/select — bog'liq yozuv yoki kerakli maydonlar; type-safe (TypeScript tekshiradi); $transaction — bir nechta amal bitta tranzaksiyada.

-------------------

9.2. PAROLNI XESHLASH
---------------------
- Ochiq matn — baza sizsa hammasi fosh; hech qachon.

9.3. BCRYPT QANDAY ISHLAYDI
---------------------------
Xesh tuzilishi: $2b$ (versiya) 12$ (cost factor: 2¹² = 4096 raund) + salt (22 belgi) + xesh (31 belgi).
- Salt — har parolga tasodifiy qiymat: bir xil parollar turli xesh beradi, tayyor (rainbow) jadvallar ishlamaydi.
- Cost (work factor) — ataylab sekin; kompyuterlar tezlashgani sari oshiriladi (odatda 10–12).
- Cheklov: parolning faqat dastlabki 72 bayti hisobga olinadi.
- Alternativlar: Argon2id, scrypt.
- Nega SHA-256 emas? U tez (brute-force osonroq), bcrypt esa ataylab sekin + salt'li.

    import bcrypt from "bcrypt";
    const ROUNDS = 12;
    const hash = await bcrypt.hash(password, ROUNDS);          // ro'yxatdan o'tish
    await User.create({ email, passwordHash: hash });
    const ok = await bcrypt.compare(password, user.passwordHash);   // kirish
    if (!ok) return res.status(401).json({ error: "Email yoki parol noto'g'ri" });

Qoidalar: parolni logga yozmang; xato xabari umumiy ("email yoki parol noto'g'ri"); minimal uzunlik 8+; brute-force'ga qarshi rate limit.

9.4. JWT (JSON WEB TOKEN)
-------------------------
Tuzilishi: HEADER . PAYLOAD . SIGNATURE
- Header: {"alg":"HS256","typ":"JWT"} — algoritm va tur.
- Payload: {"sub":"42","role":"user","exp":1798761600} — da'volar (claims): kim, rol, amal qilish muddati.
- Signature: HMAC-SHA256(base64url(header) + "." + base64url(payload), secret) — yaxlitlikni kafolatlaydi; o'zgartirilsa tekshiruv o'tmaydi.
- DIQQAT: Payload shifrlanmagan, faqat Base64URL — parol va maxfiy ma'lumotni yozmang.

Oqim: Klient POST /login {email,password} → server bcrypt.compare → jwt.sign → 200 {accessToken} → Klient GET /api/orders + Authorization: Bearer <token> → server jwt.verify (imzo va exp) → 200 OK (yoki 401/403).

    const token = jwt.sign({ sub: user.id, role: user.role },
                           process.env.JWT_SECRET, { expiresIn: "15m" });
    
    function auth(req, res, next) {
      const [, token] = (req.headers.authorization ?? "").split(" ");
      try {
        req.user = jwt.verify(token, process.env.JWT_SECRET, { algorithms: ["HS256"] });
        next();
      } catch {
        res.status(401).json({ error: "Unauthorized" });
      }
    }

JWT xavfsizlik qoidalari:
1. Qisqa muddat — access token 5–15 daq; yangilash uchun alohida refresh token.
2. Kuchli maxfiy kalit — kamida 32 tasodifiy bayt; .env yoki sirlar menejerida.
3. Algoritmni belgilang — verifyda algorithms ro'yxati ("alg: none" hujumidan himoya).
4. Payload ochiq — faqat minimal ma'lumot.
5. Xavfsiz saqlash — httpOnly + Secure + SameSite cookie; localStorage XSS'ga zaif.
6. Bekor qilish — refresh tokenni bazada saqlash, rotatsiya, logout'da o'chirish.
7. Xatoda 401 qaytaring, sababini oshkor qilmang.

9.5. RBAC (ROLLAR BO'YICHA AVTORIZATSIYA)
-----------------------------------------
- user -> O'qish: Ha; Yaratish: Yo'q; O'chirish: Yo'q
- manager -> O'qish: Ha; Yaratish: Ha; O'chirish: Yo'q
- admin -> O'qish: Ha; Yaratish: Ha; O'chirish: Ha

Eng kam huquq tamoyili — har rolga faqat zarur amallar; tekshiruv server tomonida, har himoyalangan endpointda.
    const allow = (...roles) => (req, res, next) =>
      roles.includes(req.user.role) ? next() : res.sendStatus(403);
    
    app.delete("/users/:id", auth, allow("admin"), removeUser);

DIQQAT: Rol yetarli emas: GET /orders/:id da resurs egasini ham tekshiring (order.userId === req.user.sub), aks holda — OWASP API1: BOLA.

9.6. KIRUVCHI MA'LUMOTLAR VALIDATSIYASI
---------------------------------------
Mijozga ishonib bo'lmaydi: serverda tur, format, uzunlik, diapazonni tekshiring; noma'lum maydonlarni rad eting (whitelist). Xato → 400 Bad Request. SQL uchun parametrli so'rovlar (injection'dan himoya).
    // Joi
    const schema = Joi.object({
      email: Joi.string().email().required(),
      age: Joi.number().integer().min(18),
      password: Joi.string().min(8).max(72).required(),
    });
    const { error, value } = schema.validate(req.body, { stripUnknown: true });
    if (error) return res.status(400).json(error);
    
    // Zod
    const schema = z.object({
      email: z.string().email(),
      age: z.number().int().min(18).optional(),
      password: z.string().min(8).max(72),
    }).strict();
    const r = schema.safeParse(req.body);
    if (!r.success) return res.status(400).json(r.error);

9.7. CORS
---------
Brauzer boshqa origin'ga so'rov yuboradi (avval preflight: OPTIONS) → server Access-Control-Allow-Origin va boshqa sarlavhalarni qaytaradi → origin ruxsat etilgan bo'lsa brauzer asosiy so'rovni bajaradi, aks holda bloklaydi.
    import cors from "cors";
    app.use(cors({
      origin: ["https://app.example.uz"],
      methods: ["GET","POST","PUT","DELETE"],
      credentials: true,
    }));

- Origin'larni aniq ro'yxat bilan bering; production'da origin: '*' ishlatmang.
- Access-Control-Allow-Origin: * va credentials: true birga ishlamaydi.
- DIQQAT: CORS — brauzer siyosati, server himoyasi emas: curl yoki Postman uni chetlab o'tadi.

9.11. XULOSA VA NAZORAT SAVOLLARI
---------------------------------
1. Risk = ehtimollik × ta'sir.
2. DoD "tayyor" mezonini belgilaydi.
3. Parol faqat bcrypt kabi sekin xesh bilan saqlanadi.
4. JWT: qisqa muddat, kuchli kalit; 401 = autentifikatsiya xatosi (kim ekanligi noma'lum), 403 = ruxsat yo'q (kimligi ma'lum, huquqi yo'q).
5. Validatsiya, CORS, .env, OWASP — har API uchun nazorat ro'yxati.

Savollar: parol uchun nega SHA-256 emas bcrypt (tez + salt yo'q → brute-force/rainbow); 401 va 403 qachon; CORS nega serverni himoya qilmaydi (faqat brauzer qo'llaydi, curl/Postman chetlab o'tadi).
